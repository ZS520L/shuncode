# ShunCode

> 把自定义 API、Codex 账号和网页版 AI，变成真正能操作本地项目的编程 Agent。

ShunCode 是一款基于 Code-OSS 深度定制的本地 AI 代码编辑器。它吸收了 Cursor、Windsurf、Claude Code、Codex CLI、OpenCode 等主流 AI 编程产品已经验证的交互共识：**先理解项目，再规划任务；使用工具读取、搜索、修改和验证；并行执行可以并行的工作；所有改动都可审阅、可追踪、可回滚。**

与封闭的一体化订阅不同，ShunCode 同时提供三条模型接入路径：

1. **自定义 API**：接入兼容 OpenAI Chat Completions 或 Responses API 的云端及本地模型。
2. **Codex 账号授权**：通过 OpenAI 官方授权页面登录，使用 ChatGPT 订阅中的 Codex 能力。
3. **Bridge 桥接**：把本地工作区作为 MCP Server，接入支持自定义 MCP Connector 的 ChatGPT、Claude、Grok 等网页 AI。

你可以按成本、模型能力、隐私要求和使用场景自由切换，不被单一模型厂商或单一计费方式锁定。

## 一句话定位

ShunCode 不是简单的“聊天窗口 + 代码复制按钮”，而是一套运行在编辑器内部的 Agent 工作台：

```text
理解项目 → 搜索与定位 → 制定方案 → 安全修改 → 执行命令 → 读取诊断 → 验证结果 → 汇报交付
```

它既保留图形化 IDE 的低门槛、Diff 审阅和插件生态，也具备命令行 Agent 的工具自由度、自动执行能力和长任务处理能力。

## 核心优势

### 1. 原生 Agent，而不是外挂聊天框

- Chat、模型选择、工具调用、任务进度、终端输出和代码 Diff 都在编辑器内完成。
- AI 可以自主读取项目、搜索代码、定位定义与引用、修改多个文件、执行测试并检查诊断。
- 工具结果会进入后续上下文，模型可以连续完成多步骤任务，而不是每一步都要求用户复制粘贴。
- 支持流式输出、取消执行、超时控制、失败重试和可恢复检查点，长任务中断后不必从头开始。

### 2. Ask / Plan / Code 三种工作模式

| 模式 | 适用场景 | 权限边界 |
|------|----------|----------|
| **Ask** | 解释代码、回答问题、分析现状 | 只读，不修改文件，不运行命令 |
| **Plan** | 调研项目、评估方案、拆解实施步骤 | 只读，输出可执行计划和验证方案 |
| **Code** | 实际开发、修复、重构、测试与交付 | 可读取、修改、执行和验证 |

明确的权限分层可以减少误操作：需要讨论时不动代码，需要实施时再进入 Code 模式。

### 3. 并行工具调用，提高复杂任务效率

- Agent Runtime 单批最多可并行执行 **8 个工具调用**。
- 多文件读取、文件查找和搜索支持批量请求，减少模型与工具之间的往返次数。
- 多条互不依赖的终端任务可以使用独立持久 PTY 并行运行。
- 模型可以同时调查多个模块，再汇总结果，而不是按文件串行等待。
- 工具输出记录执行耗时、并行批次和错误状态，便于模型判断下一步。

并行不是盲目地同时修改文件。涉及写入时，ShunCode 会进行补丁预检、版本校验和并发写入保护，在效率与安全之间保持平衡。

### 4. 安全、可验证的代码修改

ShunCode 使用结构化 `apply_patch` 作为主要修改工具：

- 一次调用可以新增、更新、移动或删除多个文件。
- 修改前检查上下文是否精确匹配，避免补丁落到错误位置。
- `read_files` 返回文件版本哈希；写入时可通过 `expected_versions` 检测文件是否已被用户或其他任务修改。
- 整个补丁先预检再写入，后续 hunk 失败时不会留下前半段修改。
- 保留 UTF-8 BOM、CRLF/LF 等原始文件格式。
- 返回由真实修改结果生成的标准 Unified Diff，而不是相信模型自己描述的修改。
- 同一文件的并发写入会被串行化，过期写入会明确返回冲突。

这套机制借鉴了现代 Agent 编程工具“可审阅、可回滚、拒绝静默覆盖”的行业实践。

### 5. IDE 语义能力，而不只依赖文本搜索

ShunCode 直接调用当前 VS Code 语言服务：

- 工作区符号和文档符号
- 跳转定义
- 查找引用
- 查找实现
- Hover 类型与文档信息
- 当前错误、警告、提示和未保存文件诊断

模型可以先用文本搜索定位，再用 LSP 验证语义关系，降低仅凭字符串匹配产生的误判。

### 6. 真正可交互的持久终端

- Windows 使用 Node PTY + ConPTY，提供独立于用户终端配置的持久 PowerShell。
- POSIX 环境使用持久 Bash/Sh。
- 支持交互式输入、REPL、安装提示、终端尺寸和 TTY 感知程序。
- 命令超时后不会被强制杀死，可继续通过命令 ID 读取增量输出。
- 支持后台服务器、Watcher、长时间构建和多个并行终端。

这比一次性 `exec` 更适合真实开发任务，例如启动开发服务器、等待编译、输入确认或持续读取日志。

### 7. 上下文按需读取，减少无效 Token 和卡顿

- “+”菜单和拖动只保留文件、文件夹、终端三类清晰上下文。
- 文件与文件夹默认只传名称和路径，不在发送前递归扫描或整包注入内容。
- 模型真正需要内容时，再调用目录、搜索和读取工具。
- 终端上下文使用有行数与字符数上限的文本快照。
- 图片文件通过路径引用；`Ctrl+V` 粘贴图片可作为真实视觉输入发送给支持图片的模型。
- 大文件、搜索结果和工具输出均有明确边界与截断标记，避免一次请求吞掉全部上下文窗口。

## 三种模型接入方式

### 方式一：自定义 API

Chat 模式可直接配置自己的模型服务：

- 支持 **OpenAI Chat Completions** 协议。
- 支持 **OpenAI Responses API** 协议。
- 自动从 `GET /models` 加载模型列表；不提供该接口的服务可手动填写模型 ID。
- API Key 使用 Secret 配置，不需要写入项目文件。
- 可配置 Thinking、Reasoning Effort、上下文窗口、最大输出 Token、Temperature、Top P、Stop、Seed、惩罚参数等。
- 可配置首 Token 超时、空闲超时、总超时、重试次数、并行工具调用和最大工具调用数。
- 兼容 OpenAI、DeepSeek、OpenRouter 及其他实现相应 OpenAI 协议的服务，也可连接提供兼容接口的本地推理服务。

这条路径适合需要自选模型、自控成本、连接企业网关或本地模型的用户。

### 方式二：Codex 官方授权链路

ShunCode 内置 Codex 账号页：

- 通过 `auth.openai.com` 的 OAuth 2.0 Authorization Code + PKCE 流程登录。
- 浏览器完成授权，不要求用户手动复制访问 Token。
- 凭据格式与官方 Codex CLI 兼容，默认共享 `~/.codex/auth.json`。
- ShunCode 与官方 Codex CLI 可以复用同一登录状态。
- 自动刷新账号状态和 Codex 模型目录。
- 使用 OpenAI Responses 协议、推理等级和并行 Tool Call 能力。

是否可用、可用模型、额度和速率限制取决于 OpenAI 账号、订阅方案及其当前政策。ShunCode 不出售或共享 OpenAI 账号。

### 方式三：Bridge 桥接网页版 AI

Bridge 会把当前 ShunCode 工作区暴露为受保护的 **Streamable HTTP MCP Server**。支持自定义 MCP Connector 的网页 AI 可以直接调用本地工具：

- 读取和搜索项目
- 应用多文件补丁
- 执行命令并读取输出
- 调用 LSP 与诊断
- 汇报任务进度

这样可以复用用户已有的 ChatGPT、Claude、Grok 等网页订阅，而不需要把网页版对话手工复制到编辑器。各平台是否开放自定义 MCP、支持的账户范围及使用限制，以对应平台当前政策为准。

#### Bridge 的三种隧道方式

| 方式 | 地址特征 | 适用场景 |
|------|----------|----------|
| **Cloudflare Quick Tunnel** | 自动生成临时公网地址 | 最快开始、临时使用、无需提前配置域名 |
| **Cloudflare Named Tunnel** | 固定域名 + Tunnel Token | 长期使用、稳定 Connector 地址、适合持续配置 |
| **ngrok Reserved Domain** | 固定 ngrok 域名 | 已有 ngrok 账号或保留域名的用户 |

Bridge 还包含：

- Windows 下通过 Winget 一键安装并检查 `cloudflared`。
- 本地和公网健康检查，确认 Connector 地址真正可访问后才报告就绪。
- Token 化 MCP 路径，避免裸露一个无保护的固定入口。
- Tunnel Token 和授权信息保存在 Secret Storage。
- 支持持久模式、重新生成入口和切换隧道提供商。
- 同一 Bridge 账号同时最多保留 **2 台有效设备**；新设备授权时自动替换最久未活动设备，不会同时授权第三台。

## 为什么它效率高

ShunCode 的效率来自工具设计和调度，而不是只依赖更长的 Prompt：

1. **先搜索后读取**：未知位置先搜索，定位后只读取需要的文件和行范围。
2. **批量调用**：多个文件、多个 Glob、多个搜索条件尽量在一个工具调用中完成。
3. **并行调查**：互不依赖的工具调用最多 8 路并行。
4. **持久执行环境**：命令、目录、环境变量和后台进程可以跨调用保持。
5. **增量输出**：长任务只读取新输出，不重复把全部日志发送给模型。
6. **结构化诊断**：优先读取 IDE 诊断，不需要模型从海量编译日志中猜测错误。
7. **按需上下文**：文件夹不递归灌入 Prompt，图片和大文件不会无条件编码上传。
8. **写入防冲突**：版本哈希和补丁预检减少返工与静默覆盖。

## 快速开始

1. 下载并安装 `ShunCode-0.5.7-win32-x64-Setup.exe`。
2. 打开一个项目文件夹。
3. 选择一种模型接入方式：
   - 在模型管理中添加自定义 API；
   - 登录 Codex 账号；
   - 或启动 Bridge 并把 MCP 地址添加到网页 AI。
4. 在 Chat 中选择 Ask、Plan 或 Code。
5. 描述目标，让 Agent 自己读取项目、修改代码并执行验证。

推荐工作方式：

```text
复杂需求：Plan → 审阅计划 → Code → 运行测试 → 审阅 Diff
简单问题：Ask
明确修改：Code
```

## 数据、隐私与安全边界

- 项目工具在本地 ShunCode 进程中执行。
- ShunCode 自有许可服务不接收你的源代码、对话内容或模型 API Key。
- 自定义 API 请求会发送到你配置的模型服务，数据处理受该服务条款约束。
- Codex 请求和账号数据受 OpenAI 的服务条款与隐私政策约束。
- Bridge 数据会通过你选择的 Cloudflare 或 ngrok 隧道传输到对应网页 AI，受隧道服务商和 AI 平台政策约束。
- API Key、Tunnel Token、登录 Token 和本地安装 ID 使用编辑器 Secret Storage 或对应官方凭据文件保存。
- 对敏感仓库启用 Bridge 前，请确认第三方平台、隧道和组织安全政策允许该数据流向。
